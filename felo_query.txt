SLIDE 4: PROBLEM STATEMENT - Five challenges: 1 Fixed reporting wastes bandwidth and is slow for emergencies. 2 Undetected sensor failures (NaN, -127C). 3 Unencrypted LoRa vulnerable to attacks. 4 No remote actuator control. 5 Cloud dependency fails without internet in remote farms.

SLIDE 7: SYSTEM COMPONENTS - ESP32 Node 30-pin (WiFi AP, 15 GPIO, web config). ESP32 Node 38-pin (NFC-only, 24 GPIO, PN532, light sleep). ESP32 HQ Gateway (LoRa RX, decrypt, HTTP forward). Priority engine with threshold bands: pH less than 5.5 HIGH, Temperature above 35C HIGH, Turbidity above 1000 NTU HIGH. Adaptive intervals: LOW 15min, MEDIUM 5min, HIGH 1min plus immediate dispatch. Store-and-forward FIFO retry queue max 12 packets 30s retry. Light sleep.

SLIDE 11: LORA PROTOCOL - Packet: HEADER 23B, NONCE 16B, ENCRYPTED PAYLOAD, CRC32 4B. Binary payload: num_readings 1B, pin 1B, type 1B, value 2B. 70% smaller than text. Auth key in registration only saves 8-10 bytes per telemetry packet.

SLIDE 12: ENCRYPTION - AES-128-CTR: no padding, semantic security, mbedTLS hardware accelerated. Unique 16-byte nonce per packet. CRC32 validated before decryption. HMAC-SHA256 HTTP with X-API-Key, 5-minute timestamp window, X-Signature. Chat-ID allowlist for Telegram. X-Node-Key config protection.
