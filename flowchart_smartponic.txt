================================================================================
                    NODE REGISTRATION FLOW (38-PIN NFC VARIANT)
================================================================================

  [1] Node powers on → STATE_REGISTERING
  [2] Node sends "hello" registration packet via LoRa
  [3] HQ receives "hello" → validates → sends "approve" downlink
  [4] Node receives "approve" → STATE_CONNECTED
  [5] Node begins normal telemetry reporting
  [6] If 5 consecutive ACKs missed → back to STATE_REGISTERING

================================================================================
                    SECURITY LAYERS
================================================================================

  +------------------------------------------------------------------+
  | 1. LoRa Packets:  AES-128-CTR encryption + random 16B nonce     |
  |                    CRC32 integrity check per packet               |
  | 2. HTTP API:       HMAC-SHA256(timestamp + body + secret)        |
  |                    Timestamp replay protection (5 min window)     |
  |                    Shared API key in header                       |
  | 3. Node Access:    Security key stored in ESP32 Preferences      |
  |                    Required for config changes                    |
  | 4. NFC Payloads:   AES-128-CTR encrypted with 16B IV             |
  | 5. Telegram:       Chat ID allowlist for access control          |
  +------------------------------------------------------------------+
