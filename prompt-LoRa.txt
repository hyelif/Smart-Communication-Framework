==================================================
SYSTEM ARCHITECTURE
==================================================

Node Site:
ESP32 + Sensors + LoRa → sends encrypted telemetry every 30s

HQ Site:
ESP32 + LoRa → receives, decrypts, validates, logs

Communication is PURE LoRa — no WiFi, no HTTP, no backend.

==================================================
HANDSHAKE PROTOCOL
==================================================

Node boots in STATE_REGISTERING:
- Sends registration packet every 5s:
  auth=<AUTH_KEY>&aes_key=<AES_KEY>&cmd=hello
- Listens for approval from HQ

HQ receives registration:
- Validates auth key matches
- Sends approval: auth=<AUTH_KEY>&cmd=approve&hardware_id=<HW_ID>

Node receives approval → STATE_CONNECTED:
- Starts 30s telemetry cycle

==================================================
KEEP-ALIVE / ACK MECHANISM
==================================================

After each telemetry packet:
- HQ sends cmd=ack back to the node
- Node actively waits for ACK for 3s after TX
- Tracks gMissedAckCount (consecutive misses)
- After 5 missed ACKs → falls back to STATE_REGISTERING
- Only processes packets addressed to its own hardware_id
- Auto-recovers when HQ comes back online

==================================================
PACKET STRUCTURE
==================================================

Binary packet: [HEADER:23][NONCE:16][ENCRYPTED_PAYLOAD][CRC32:4]

Header (23 bytes):
  - magic:        uint32_t (0x31504653 = "SPF1")
  - version:      uint8_t  (0x01)
  - hardwareId:   uint8_t[16] (16-char uppercase hex from ESP.getEfuseMac())
  - payloadLength: uint16_t (encrypted payload size, little-endian)

Encryption: AES-128-CTR via mbedtls
Integrity: CRC32 (validated before decryption)
Max packet: 255 bytes
